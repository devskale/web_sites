## Architecture

```
Browser → https://lubu.skale.dev (amd :443, TLS)
       → amd nginx proxy (Host: lubu.skale.dev)   [was neusiedl — fixed]
       → home lubu :8001 nginx vhost lubu.skale.dev
       → /family /admin /normie → auth_request gate
       → oauth2-proxy (127.0.0.1:4180) → Google
       → role gate → admin API (127.0.0.1:8180) checks roles.txt
```

**Two boxes involved:** amd (Oracle Cloud, 138.2.179.13) reverse-proxies
`lubu.skale.dev` → home lubu (`194.96.252.52:8001`). DNS `lubu.skale.dev` →
amd. Home router owns :443 (Zyxel admin UI), so home serves on alt ports.

## Key fixes made this session

1. **amd proxy Host header** was `neusiedl.duckdns.org` → home routed to wrong
   vhost → `/family/` 404. Fixed to `Host: lubu.skale.dev` on amd.
2. **Login redirect picked up `:8001`** → added `absolute_redirect off;` in the
   home `@oauth_redirect` so it stays relative and resolves against the clean URL.
3. **DNS**: `lubu.skale.dev` CNAME chain was stale. Forced all-inkl DDNS
   (`~/code/freedns/allinkl-ddns.sh --force`) → `lubudyn.skale.dev` → current IP.
   (Note: `lubu.skale.dev` is a CNAME → `lubudyn.skale.dev` at all-inkl; managed
   via KAS panel, no API.)

## Auth hardening (best practices) — in oauth2-proxy.cfg

- `trusted_proxy_ips = ["127.0.0.1","::1"]` (only nginx sets X-Forwarded-*)
- `whitelist_domains = ["lubu.skale.dev"]` (prevents open-redirect)
- `cookie_secure=true`, `cookie_samesite="lax"`, `cookie_csrf_samesite="lax"`
- `insecure_oidc_skip_nonce=false` (verify nonce)
- `pass_authorization_header/access_token/basic_auth=false` (don't leak upstream)
- `prefer_email_to_user=true`, `cookie_refresh="7h"`, `scope="openid email profile"`
- Custom "under review" error page at `/etc/oauth2-proxy/templates/error.html`

## Role-based access

- Roles file: `/etc/oauth2-proxy/roles.txt` (`email role`, roles: admin|normie)
- nginx `auth_request` gates: `/role-gate` (any role) → `/normie/`;
  `/role-gate-admin` (admin) → `/admin/` + `/api/users`. Gate authenticates via
  oauth2-proxy then asks backend. `X-Auth-Request-Email` set by nginx (unspoofable).
- Backend API (admin only): `GET /api/users`, `POST /api/users/<email>` (set role,
  also approves), `DELETE /api/users/<email>` (ban).
- **Current users:** jwamind@gmail.com = admin; woodmastr2015@gmail.com = normie.

## How to use / operate

- **Approve/role/ban:** log in as jwamind → `https://lubu.skale.dev/admin/`.
- **CLI fallback:** `sudo oauth2-approve add <email>` (approve only; roles via
  editing roles.txt).
- **Watch login attempts:** `sudo oauth2-approve watch` / `attempts`.
- **Restart services:** `sudo systemctl restart oauth2-proxy lubu-admin-api`.
- **Edit site:** files in the git repo are served live; `git commit` + `push`
  after changes (nginx config changes need `sudo nginx -t && sudo systemctl reload nginx`).
